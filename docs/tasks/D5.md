# D5 – Monitorowanie: odświeżanie przyrostowe i CLI

**Właściciel:** O1 · **Zależności:** !D2, ~D1 · **Status:** patrz [`PROGRESS.md`](../../PROGRESS.md)

## Cel
Monitorowanie w czasie: cykliczne dociąganie nowych opinii dla obserwowanych obiektów, także bez otwartego GUI (cron).

## Zakres
- CLI `python -m opimon.cli` (argparse) korzystające z `build_services()`.
- Dziennik pobrań per cel (kiedy, ile, błędy).

## Pliki (własność)
- `opimon/cli.py` – nowy
- `opimon/storage/fetch_log.py` (lub tabela w SQLite D2) – nowy
- `opimon/services.py` -> `refresh_all` – edycja
- `tests/test_cli.py` – nowy

## Kontrakt / API
`python -m opimon.cli refresh|add|list|remove`. Dziennik pobrań widoczny w D4.

## Kryteria akceptacji
- [ ] `refresh [--limit N]` pobiera przyrostowo nowe opinie dla wszystkich celów i je analizuje
- [ ] `add <źródło> <zapytanie|klucz>`, `list`, `remove <target_id>`
- [ ] Dziennik pobrań per cel (czas, liczby, błędy) zapisany w bazie i widoczny w D4
- [ ] Błąd jednego celu nie przerywa pozostałych; kod wyjścia ≠ 0, gdy były błędy
- [ ] Instrukcja uruchamiania z cron / systemd timer w README
- [ ] Testy CLI na źródle przykładowym i bazie tymczasowej

## Wskazówki
- GUI czyta bazę przy każdym odświeżeniu, więc zmiany z CLI są widoczne bez restartu.

## Poza zakresem
- Wbudowany scheduler w procesie Streamlit.
