## Zakres
- `SqliteReviewRepository` implementujący `ReviewRepository`.
- Schemat: `targets`, `reviews`, `predictions` (+ indeksy), migracja przez `CREATE TABLE IF NOT EXISTS`.
- Bezpieczny dostęp z wielu wątków Streamlit i z drugiego procesu (WAL).

## Kryteria akceptacji
- [ ] `SqliteReviewRepository` przechodzi test kontraktowy (dopisany do `REPOSITORY_FACTORIES`)
- [ ] Schemat: `targets`, `reviews`, `predictions` z kluczami głównymi i indeksami po (`target_id`, `created_at`) i `model_name`
- [ ] Daty zapisywane w UTC, odczytywane jako aware; `extra` jako JSON; `label` jako NULL / tekst
- [ ] `config.DB_PATH` czytany w chwili wywołania; brakujący katalog tworzony automatycznie
- [ ] Dane przetrwają „restart” (test: dwa obiekty repozytorium na jednym pliku)
- [ ] Dostęp wielowątkowy (`check_same_thread=False` + lock albo połączenie per wątek) i `journal_mode=WAL`
- [ ] `_make_repository()` zwraca SQLite; wszystkie testy przechodzą

## Wskazówki
- `add_reviews` -> `INSERT OR IGNORE` + `changes()` / `rowcount`; `save_predictions` -> `INSERT OR REPLACE`.
- Sortuj w SQL: `ORDER BY created_at DESC, id ASC`; daty zapisuj jako ISO 8601 w UTC, wtedy porównania tekstowe są poprawne.
- `remove_target` usuwa kaskadowo (`ON DELETE CASCADE` + `PRAGMA foreign_keys=ON`) albo w jednej transakcji.
