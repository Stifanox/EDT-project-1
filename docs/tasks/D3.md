# D3 – Źródło przez web scraping (Metacritic: filmy i gry)

**Właściciel:** O1 · **Zależności:** !P0, ~D1 · **Status:** patrz [`PROGRESS.md`](../../PROGRESS.md)

## Cel
Drugie źródło, tym razem przez web scraping, zgodne domenowo ze zbiorem treningowym IMDB: recenzje filmów z oceną 1–10. Spełnia wariant „web scraping” z wytycznych.

## Zakres
- Wybór serwisu (propozycja: recenzje użytkowników IMDb; zapas: Letterboxd / Metacritic) po sprawdzeniu `robots.txt` i regulaminu, cel edukacyjny, mały wolumen.
- Parser HTML (BeautifulSoup) + wyszukiwanie filmu po tytule.
- Etykieta jak w zbiorze IMDB: ocena ≥ 7 -> pozytywna, ≤ 4 -> negatywna, w przeciwnym razie brak.

## Kontrakt / API
Udostępnia `ReviewSource`. `Target.key` = `movie/<slug>` lub `game/<slug>` (np. `movie/dune-part-two`).

## Kryteria akceptacji
- [x] Wybór serwisu uzasadniony w notatkach (sprawdzony `robots.txt` i regulamin, User-Agent projektu, limit zapytań)
- [x] Źródło przechodzi test kontraktowy OFFLINE na zapisanych stronach HTML w `tests/fixtures/`
- [x] `find_targets` znajduje filmy po tytule (z rokiem w `Target.name`)
- [x] Ocena -> `rating`; `label` według progów IMDB (≥ 7 / ≤ 4 / brak); spoilery i „Read more” usunięte (`clean_text`)
- [x] Daty sparsowane do UTC; `limit` i `since` działają (jedna strona = 50 najnowszych recenzji, serwis nie stronicuje HTML – patrz notatki)
- [x] Zmieniona struktura strony -> `SourceError` „Nie rozpoznano struktury strony …” (test na uciętym HTML)
- [x] Wariant `-m network` przechodzi

## Wskazówki
- Wiele serwisów osadza dane w `<script type="application/ld+json">` albo `__NEXT_DATA__`. Parsowanie JSON jest stabilniejsze niż selektory CSS.
- Jeśli strona wymaga JavaScriptu, zmień serwis zamiast dodawać Selenium/Playwright. Decyzję zapisz w dzienniku.
- Zapisz 2–3 strony HTML jako fixture raz i testuj wyłącznie offline.

## Poza zakresem
- Obchodzenie zabezpieczeń anty-botowych, logowanie, proxy.

## Notatki z realizacji
**Zrobione 2026-11-04, 7/7.** Kryterium 5 zmienione: było „paginacja do `limit`” (patrz „Ograniczenia”).

**Wybór serwisu: Metacritic** (decyzja użytkownika, O1). Sprawdzenie 2026-11-04 z User-Agentem projektu:

| Serwis | robots.txt (`User-agent: *`) | Strona recenzji | Wynik |
|--------|------------------------------|-----------------|-------|
| IMDb | `Disallow: /` | – | odrzucony (zakaz dla wszystkich) |
| Letterboxd | recenzje dozwolone | HTTP 403 dla naszego klienta | odrzucony |
| Rotten Tomatoes | recenzje dozwolone | recenzje widzów ładowane JavaScriptem | odrzucony |
| **Metacritic** | zakazane `/search`, `/user`, `/login`; `/<movie\|game>/<slug>/user-reviews/` dozwolone | HTML renderowany na serwerze | **wybrany** |

- Regulaminu Metacritic (Fandom) nie udało się pobrać automatycznie (403/404). Serwisy tego typu
  zwykle zastrzegają zgodę na zautomatyzowany dostęp. **Przed oddaniem projektu przeczytajcie
  regulamin.** Źródło ogranicza się do celu edukacyjnego i małego wolumenu: jedna strona na pobranie,
  odstęp `config.REQUEST_DELAY_S`, uczciwy User-Agent, cache stron 120 s.
- Zgodnie z `robots.txt` źródło **nie używa `/search` ani `/user/`** (test
  `test_never_uses_disallowed_search`). Cel wskazuje się tytułem (zamienianym na slug Metacritic,
  sprawdzane są film i gra), adresem URL albo zapisem `movie/<slug>` / `game/<slug>`.
- Zaleta: ta sama domena co zbiór treningowy (recenzje filmów z oceną 0–10, progi jak w IMDB),
  a do tego gry, więc da się porównać z danymi ze Steam (M5).

**Parsowanie** (`parse_user_reviews`, czysta funkcja):
1. Podstawowo osadzony stan Nuxt `<script id="__NUXT_DATA__">` (format *devalue*: spłaszczona
   tablica JSON z odwołaniami po indeksach; rozwijana przez `_devalue`). Daje stabilne id (UUID),
   pełny tekst (także recenzji ze spoilerami, które w HTML są ukryte), ocenę, autora i czas:
   `version` (ms) jako dokładny czas, jeśli jest z dnia `date`; inaczej południe UTC.
   Produkt (tytuł, rok) wybierany po slugu, a recenzje filtrowane po `reviewedProduct.url`.
2. Zapasowo karty HTML (`data-testid="review-card"` i pokrewne, stabilniejsze niż klasy CSS).
   Brak id, więc id = `h-` + skrót SHA-1 autora, dnia i treści; czas = południe UTC; recenzje ze
   spoilerami pomijane (w HTML jest tylko „[SPOILER ALERT…]”). Test sprawdza, że oba parsery dają
   te same teksty, oceny i daty (45 recenzji bez spoilerów).
3. Brak obu -> `SourceError` „nie rozpoznano struktury strony” (testy: strona błędu, ucięty HTML).

**Ograniczenia:**
- Strona pokazuje 50 najnowszych recenzji; kolejne doładowuje JavaScript z prywatnego API
  (adres budowany w kodzie JS, nie ma go w HTML). Odtwarzanie prywatnego API to już nie scraping
  strony, więc tego nie robimy; `?page=2` zwraca tę samą stronę. Jedno pobranie daje ≤ 50 opinii,
  a monitorowanie (D5) dociąga nowe przy kolejnych odświeżeniach.
- Ok. 18% recenzji nie jest po angielsku (hiszpański, francuski, niemiecki, turecki, portugalski,
  polski). Źródło oznacza je `language="und"` (prosty detektor oparty na udziale angielskich
  stop-słów, 18/18 trafnie na fixture'ach), ale ich nie odrzuca. Filtrowanie to D6 (opcjonalny).
  Do ewaluacji i analizy warto użyć tylko `language == "en"`.
- `premiereYear` bywa pusty (np. Hades II), wtedy nazwa celu jest bez roku.
- Przy wyłączonym osadzonym stanie (parser zapasowy) daty mają dokładność do dnia, więc pobieranie
  przyrostowe w tym samym dniu może pominąć nowsze recenzje z tego dnia. Przy osadzonym stanie
  czas jest dokładny.
