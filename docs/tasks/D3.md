# D3 – Źródło przez web scraping (recenzje filmów)

**Właściciel:** O1 · **Zależności:** !P0, ~D1 · **Status:** patrz [`PROGRESS.md`](../../PROGRESS.md)

## Cel
Drugie źródło, tym razem przez web scraping, zgodne domenowo ze zbiorem treningowym IMDB: recenzje filmów z oceną 1–10. Spełnia wariant „web scraping” z wytycznych.

## Zakres
- Wybór serwisu (propozycja: recenzje użytkowników IMDb; zapas: Letterboxd / Metacritic) po sprawdzeniu `robots.txt` i regulaminu, cel edukacyjny, mały wolumen.
- Parser HTML (BeautifulSoup) + wyszukiwanie filmu po tytule.
- Etykieta jak w zbiorze IMDB: ocena ≥ 7 -> pozytywna, ≤ 4 -> negatywna, w przeciwnym razie brak.

## Pliki (własność)
- `opimon/sources/<serwis>.py` – nowy (np. `imdb.py`, `name="imdb"`)
- `opimon/sources/http.py` – edycja (wspólny klient z D1)
- `opimon/services.py` -> `_make_sources()` – edycja
- `tests/contracts/test_source_contract.py` -> `SOURCE_CASES` – edycja
- `tests/test_source_<serwis>.py`, `tests/fixtures/<serwis>/*.html` – nowe
- `requirements.txt` – `beautifulsoup4` (sekcja O1)

## Kontrakt / API
Udostępnia `ReviewSource`. `Target.key` = identyfikator filmu w serwisie (np. `tt0111161`).

## Kryteria akceptacji
- [ ] Wybór serwisu uzasadniony w notatkach (sprawdzony `robots.txt` i regulamin, User-Agent projektu, limit zapytań)
- [ ] Źródło przechodzi test kontraktowy OFFLINE na zapisanych stronach HTML w `tests/fixtures/`
- [ ] `find_targets` znajduje filmy po tytule (z rokiem w `Target.name`)
- [ ] Ocena -> `rating`; `label` według progów IMDB (≥ 7 / ≤ 4 / brak); spoilery i „Read more” usunięte (`clean_text`)
- [ ] Daty sparsowane do UTC; paginacja do `limit`; `since` działa
- [ ] Zmieniona struktura strony -> `SourceError` „Nie rozpoznano struktury strony …” (test na uciętym HTML)
- [ ] Wariant `-m network` przechodzi

## Wskazówki
- Wiele serwisów osadza dane w `<script type="application/ld+json">` albo `__NEXT_DATA__`. Parsowanie JSON jest stabilniejsze niż selektory CSS.
- Jeśli strona wymaga JavaScriptu, zmień serwis zamiast dodawać Selenium/Playwright. Decyzję zapisz w dzienniku.
- Zapisz 2–3 strony HTML jako fixture raz i testuj wyłącznie offline.

## Poza zakresem
- Obchodzenie zabezpieczeń anty-botowych, logowanie, proxy.
