# M1 – Zbiór treningowy IMDB

**Właściciel:** O2 · **Zależności:** !P0 · **Status:** patrz [`PROGRESS.md`](../../PROGRESS.md)

## Cel
Prawdziwe dane treningowe: 50 tys. recenzji filmowych IMDB (Kaggle / Hugging Face), czyszczone tak samo jak dane z Internetu.

## Zakres
- `ImdbTrainingData` (`name="imdb"`) implementujący `TrainingDataProvider`.
- Plik z Kaggle (`IMDB Dataset.csv`) w `config.DATASETS_DIR` albo pobranie z Hugging Face.
- Analiza zgodności z danymi do predykcji (długość, słownictwo).

## Pliki (własność)
- `opimon/sentiment/imdb.py` – nowy
- `opimon/sentiment/__init__.py` – edycja
- `opimon/services.py` -> `_make_training_data()` – edycja
- `tests/contracts/test_training_data_contract.py` -> `PROVIDER_FACTORIES` – edycja
- `tests/fixtures/imdb_mini.csv`, `tests/test_imdb.py` – nowe
- `scripts/download_imdb.py` – nowy (opcjonalnie)

## Kontrakt / API
Udostępnia `TrainingDataProvider`. Zbiory w `config.DATASETS_DIR`, cache w `config.CACHE_DIR`.

## Kryteria akceptacji
- [x] `ImdbTrainingData` czyta `IMDB Dataset.csv` (Kaggle) lub zbiór z Hugging Face; brak danych -> `DatasetUnavailableError` z instrukcją pobrania
- [x] Czyszczenie `textproc.clean_text` (IMDB zawiera `<br />`), tak samo jak dane z Internetu
- [x] Deterministyczny, zbalansowany podział train/test; działają `max_train` i `max_test`
- [x] Cache przetworzonego zbioru w `config.CACHE_DIR`; drugie wczytanie < 2 s
- [x] Przechodzi test kontraktowy na pliku-fixture `tests/fixtures/imdb_mini.csv`
- [x] IMDB pierwszy w `_make_training_data()`; w notatkach statystyki zbioru i porównanie z danymi Steam / IMDb (uzasadnienie spójności)

## Wskazówki
- Kaggle: *IMDB Dataset of 50K Movie Reviews* (kolumny `review`, `sentiment`). Hugging Face: `stanfordnlp/imdb` (można pobrać parquet bez biblioteki `datasets`).
- Komunikat `DatasetUnavailableError` ma podać dokładną ścieżkę, pod którą trzeba położyć plik.

## Poza zakresem
- Inne zbiory (Steam reviews z Kaggle) – ewentualnie jako dodatkowy provider po M5.

## Notatki z realizacji
- 2026-11-08: CSV Kaggle (`review,sentiment`) i eksport Hugging Face (`split`) obsługiwane.
  Pobranie: `.venv/Scripts/python.exe scripts/download_imdb.py`; publiczne pliki
  [stanfordnlp/imdb](https://huggingface.co/datasets/stanfordnlp/imdb), bez konta i tokenu.
- Oryginalny zbiór ma 50 000 przykładów, po usunięciu powtórzeń oczyszczonego tekstu,
  konfliktujących etykiet i wyrównaniu klas: train 24 862, test 24 532 (po 50% każdej klasy).
  Eksport zachowuje oficjalną przynależność train/test; CSV bez `split`: seed 13, podział 75/25.
  Cache identyfikowany wersją przetwarzania, ścieżką, rozmiarem i mtime źródła; uszkodzenie
  cache powoduje odbudowę, brak CSV zawsze zgłasza instrukcję pobrania.
- Pomiar lokalny: pierwszy odczyt około 3 s; odczyt z cache 0,43 s (< 2 s).
  Mediana długości: IMDB 173 słowa, próbka gier 14; 99,46% unikalnych tokenów próbki
  występuje w treningowym IMDB. Próbka gier jest syntetyczna, nie stanowi pomiaru Steam live.
  IMDb/D3: ta sama domena filmowa; Steam/D1: angielski, recenzje rozrywki i etykieta binarna,
  ale inne aspekty (wydajność, aktualizacje, rozgrywka) i długości — możliwa zmiana domeny.
- Weryfikacja: 89 testów offline zaliczonych, 1 pominięty; Ruff czysty;
  Streamlit `/_stcore/health` HTTP 200, widoki sprawdzone przez AppTest.
  Testy wspólne treningu jawnie wskazują `sample_movies`, gdy domyślny provider to IMDB.
- Kontrola końcowa O2: cache zapisuje się przez unikalny plik tymczasowy także przy
  równoległych odczytach CLI/GUI; niepełny CSV daje `DatasetUnavailableError`, nie surowy
  wyjątek. Wyrównywanie klas dotyczy obu formatów wejściowych. Skrypt pobrania stosuje
  timeout oraz odstęp z config. Dodano testy tych przypadków, oficjalny podział i wyniki bez zmian.
- Ponowienie wykazało, że na Windows unikalny plik tymczasowy nie wystarcza: podmiana
  może kolidować z otwartym czytnikiem. Wspólny helper O2 `sentiment/cache.py` synchronizuje
  odczyty i atomowe zapisy JSON w procesie oraz zachowuje istniejący cache przy blokadzie
  przez drugi proces. 20 niezależnych uruchomień obu testów współbieżności (IMDB i ewaluacja)
  dało 40/40 sukcesów; dodatkowy test wymusza Windows sharing violation.
